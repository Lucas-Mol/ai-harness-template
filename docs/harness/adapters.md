# Adapters — tool × feature matrix

Canonical sources: [`AGENTS.md`](../../AGENTS.md) and [`.agents/`](../../.agents/). `make harness-sync` generates
everything else for the tools listed in `harness.config.yaml: targets`. Formats were checked against each
tool's documentation on **2026-10-14** — these formats change often; re-check before relying on a new feature.

Legend: **N** = read natively from the canonical source · **G** = generated by sync · **—** = not supported / not generated.

| Feature | Claude Code | GitHub Copilot | Cursor | Codex | Gemini CLI |
|---|---|---|---|---|---|
| Instructions | `CLAUDE.md` (hand-written, imports `@AGENTS.md`) | N `AGENTS.md` + G `.github/copilot-instructions.md` | N `AGENTS.md` | N `AGENTS.md` | G `.gemini/settings.json` → `context.fileName: AGENTS.md` |
| Skills (`SKILL.md`) | G `.claude/skills/` | G `.github/skills/` | G `.cursor/skills/` | N `.agents/skills/` | N `.agents/skills/` (alias of `.gemini/skills/`) |
| Subagents | G `.claude/agents/*.md` | G `.github/agents/*.agent.md` | — | — | — |
| Commands | G `.claude/commands/*.md` | G `.github/prompts/*.prompt.md` | G `.cursor/commands/*.md` | — (skills replace repo prompts) | G `.gemini/commands/*.toml` |
| Hooks | G `.claude/settings.json` → `scripts/hooks/*` | — | — | — | — |
| Permissions | G `.claude/settings.json` (`deny`) | — | — | — | — |
| MCP servers | G `.mcp.json` | — (configured in repo settings / editor) | G `.cursor/mcp.json` | G `.codex/config.toml` | G `.gemini/settings.json` |

Tools without hooks still get the same guardrails through **pre-commit** and **CI** (`scan-secrets`,
`harness-lint`, `make check`) and **CODEOWNERS** on protected paths.

## Translations

### Subagent frontmatter (`.agents/agents/*.md`)

| Neutral | Claude Code | Copilot |
|---|---|---|
| `tools: read` | `Read, Grep, Glob` | `read, search` |
| `tools: write` | `Edit, Write` | `edit` |
| `tools: shell` | `Bash` | `execute` |
| `tools: web` | `WebFetch, WebSearch` | `web` |
| `model_hint: fast / balanced / deep` | `haiku / sonnet / opus` | omitted (model chosen in the UI) |

### Command arguments

Canonical commands use `$ARGUMENTS`. Claude keeps it; Copilot → `${input:args}`; Gemini → `{{args}}`;
Cursor → "the text provided after the command".

### MCP environment variables

`.agents/mcp/servers.yaml` lists variable **names** only. Claude/Codex reference them as `${VAR}` /
`env_vars`/`bearer_token_env_var`, Cursor as `${env:VAR}`, Gemini as `$VAR`.

## Generated-file rules

- Markdown/TOML outputs carry `GENERATED BY scripts/harness/sync — DO NOT EDIT` (after the YAML frontmatter when present).
- JSON outputs can't carry comments; every output is listed with its hash in `.agents/.generated.json` ([ADR-0003](../adr/0003-track-generated-files-with-manifest.md)).
- `protect-paths.sh` blocks agent edits to generated files; `harness-lint` (`sync --check`) fails on hand edits.
- Removing a target leaves its files as **orphans**: listed by sync and lint, deleted only with `make harness-sync ARGS=--prune` after confirmation.

## Known caveats

- Copilot also reads `.claude/skills/`; with both `claude` and `copilot` targets a skill may be listed twice.
- Codex project config (`.codex/config.toml`) is only loaded for trusted projects.
- Cursor, Codex and Gemini subagent formats are still moving; add generators in `scripts/harness/sync.py`
  (`BUILDERS`) once stable, and update this table.

## Adding a tool

1. Add the name to `KNOWN_TARGETS` in `scripts/harness/common.py`.
2. Write `build_<tool>(src) -> dict[path, bytes]` in `scripts/harness/sync.py` and register it in `BUILDERS`.
3. Add a column above, run `make harness-sync && make harness-lint`, and record the decision in an ADR if non-obvious.
